# VillAIgence 0.3.2

Vill-AI-gence — Giving villagers a mind of their own.

`0.3.2+1.21.1` is a second narrow corrective release over immutable `0.3.1+1.21.1`. It addresses the installed `VAI-PCM-MULTI-001` failure that remained after `0.3.1`: Muammer's owner-local marker event was still retained and isolated correctly, but bounded retrieval could drop it before the final prompt context.

## Fixed

- Query-aware final Memory 2.0 ranking no longer treats exact NPC/player participant matching as an extra positive relevance dimension after that same match has already been enforced as an eligibility boundary. This prevents fresh unrelated eligible dialogue from receiving a structural relevance bonus that can displace an older targeted event at rank-to-6.
- Explicit marker/code/token recall now has a deterministic bounded zero-overlap fallback for already-eligible `DIALOGUE / PLAYER_TOLD` events. The current question must express recall intent, the original player text must contain an explicit storage cue, and that text must contain a bounded machine-like opaque identifier such as `amber-pine-314` or `amber pine 314`.
- The referential score participates only in the existing query-relevant lane and final ranker. The hard Memory 2.0 bounds remain unchanged: at most 32 candidates enter the final ranking path and at most 6 results reach episodic/social prompt context.
- False-positive guards deliberately reject natural-language numeric phrases, `NPC_TOLD` dialogue, storage commands masquerading as recall queries, and unrelated machine-like identifiers such as `java-21` when the original player text contains no storage cue.

## Unchanged boundaries

This patch adds no:

- persistence schema/version change, new store or migration/backfill;
- public configuration change;
- provider request/schema/call-count change;
- semantic/vector database, embeddings or provider-assisted memory retrieval;
- larger prompt or memory candidate windows;
- weakening of NPC/player isolation or player-scoped eligibility;
- change to FACT/BELIEF authority, relationship/social authority or voice-target semantics.

Existing current-fact authority, server-owned validation, replay/idempotency contracts and release identity guarantees remain unchanged.
