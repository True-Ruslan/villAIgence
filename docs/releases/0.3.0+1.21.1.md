# VillAIgence 0.3.0

Vill-AI-gence — Giving villagers a mind of their own.

`0.3.0+1.21.1` packages the complete bounded post-`0.2.0` Memory 2.0 and Personality/NPC↔NPC social capability set through PR #158 into one exact release boundary.

## Highlights

### Bounded, provenance-aware knowledge

- controlled Semantic BELIEF admission and bounded `PLAYER_TOLD` extraction;
- causal NPC×player relationship memory;
- FACT-over-BELIEF prompt precedence and bounded long-horizon recall;
- exact source-backed NPC-to-NPC knowledge transfer;
- immutable bounded multi-hop rumor provenance;
- deterministic disagreement/contradiction representation and prompt context;
- explicit rumor fallibility and one bounded server-owned transformed-claim primitive;
- bounded automatic contradiction production;
- settlement-scale information flow without shared omniscience;
- NPC×player trust as a bounded prompt-only social-epistemic view, never truth authority.

### Personality and NPC↔NPC social state

- MCA `VillagerBrain` Personality remains the sole persistent personality authority;
- dedicated world-local `npc-social-graph.json` stores bounded directed NPC→NPC trust, respect, fear and affinity independently from NPC×player `relationships.json`;
- causal exactly-once social mutation requires exact retained server-owned evidence and persists a source-local replay frontier atomically with graph state;
- immutable read-only snapshots expose only canonical Personality plus one exact directed NPC pair;
- dialogue guidance is closed, deterministic and bounded;
- selected settlement knowledge transfer may be suppressed by the exact directed social pair without retargeting or graph enumeration;
- `follow-player` is revalidated immediately before execution against fresh strict NPC×player relationship authority;
- malformed authority-sensitive persistence fails closed rather than recovering into an allowed state.

## Authority boundary

The LLM remains non-authoritative.

```text
current server-observed facts
→ bounded Personality/direct-social context
→ bounded server-authored dialogue guidance
→ Operator Lore
→ Semantic Memory
→ live disagreement context
→ episodic/social history
→ structured provider/tool instructions
→ provider proposal
→ server validation/revalidation
→ server-owned mutation
```

Social state, confidence, repetition, provenance depth, fallibility and wording transformations do not promote BELIEF to FACT. Provider output cannot directly author NPC social graph deltas or bypass server-owned gameplay validation.

## Automated release assurance

The exact release-request candidate must pass the complete release matrix on one frozen head:

- repository security policy;
- common/unit and deterministic mock-provider tests;
- required Fabric server GameTests;
- Fabric and NeoForge builds;
- exact production startup, controlled stop/save and same-world restart;
- six-store destructive auxiliary recovery;
- Production Soak under constrained concurrency and repeated restarts;
- distributable package verification;
- byte-for-byte equality between the production-accepted and packaged JAR;
- GitHub Release dry-run with publication skipped before merge.

The immutable tag and GitHub Release are created only after the dedicated release request reaches `1.21.1` and the same release workflow passes on that exact main commit.

## Explicit non-scope

`0.3.0` does not add:

- high-frequency/per-tick autonomous LLM agents;
- graph-neighborhood enumeration/ranking or fallback social target selection;
- open-ended provider-authored social mutation;
- autonomous visible NPC↔NPC LLM conversations;
- factions/politics;
- settlement-global truth authority;
- the future 0.4 richer knowledge-ecosystem expansion.
