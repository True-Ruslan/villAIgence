# VillAIgence 0.2.0

Vill-AI-gence — Giving villagers a mind of their own.

This release begins the 0.2 Memory 2.0 line and promotes the persistent-dialogue clean cutover completed after `0.1.26+1.21.1`.

## Breaking pre-1.0 data boundary

`0.2.0` intentionally does **not** migrate the experimental pre-0.2 `<world>/livingworld/memory.json` conversation store.

Supported rollout for this development release is a clean LivingWorld state. The old raw conversation store is no longer opened, imported or recovered by the current runtime.

Do not point this candidate at the only copy of a valuable world. Use a dedicated test world or an offline copy and retain backups before validation.

## Memory 2.0 dialogue cutover

Persistent dialogue now uses one canonical path:

```text
successful text/voice turn
→ ChatAI post-success boundary
→ Memory2DialogueLifecycle
→ structured DIALOGUE MemoryEvent
→ memory2.json

next turn
→ exact NPC/player DIALOGUE retrieval
→ filter before limit
→ chronological user/assistant reconstruction
→ Working Memory bounds
→ prompt
```

New DIALOGUE events carry a structured `DialogueExchange(playerMessage, npcReply)` payload in addition to their bounded human-readable episodic summary. Prompt reconstruction reads the structured payload and never parses the summary.

The retrieval path:

- isolates the exact NPC and player pair;
- ignores unrelated NPC/player dialogue;
- filters eligible dialogue before applying the result limit;
- restores chronological `user` / `assistant` ordering;
- applies existing Working Memory hard bounds;
- ignores historical summary-only DIALOGUE records instead of guessing their roles.

`ConversationMemoryStore`, `MemoryMessage`, `memory.json` recovery and the old six-store current acceptance dependency are removed. `PersistentChatMemory` remains only as a no-storage compatibility adapter for the inherited AI call surface; it reads Memory 2.0 and does not perform a second persistent write.

## Current persistence boundary

The current destructive auxiliary-store recovery matrix covers:

```text
memory2.json
semantic-memory.json
relationships.json
voices.json
operator-lore.json
```

`events.json` remains authoritative factual event history with its own validation path.

Release recovery remains version-aware: historical immutable releases are rebuilt and validated against the contracts present at their own tag commit, so `0.1.26` retains its historical six-store evidence without forcing that model onto `0.2.0`.

- required Fabric server GameTests;
- Fabric and NeoForge builds;
- exact production Fabric startup, clean stop/save and same-world restart;

- constrained-heap production restart soak;
- distributable package smoke;

- non-publishing release dry-run on the exact PR head.

## Installed clean-world acceptance

Publication remains blocked until the exact dry-run candidate is installed on the operator test server using a clean LivingWorld state and the focused Memory 2.0 installed plan passes.

Required installed boundaries:

1. clean startup with no blocking VillAIgence/Mixin/refmap/injection errors;
2. first text dialogue persists;
3. next text turn recalls the unique test phrase;
4. another NPC does not receive that dialogue history;
5. one physical voice turn persists into the same DIALOGUE model;
6. clean server restart preserves recall in the same world;
7. `memory2.json` exists and `memory.json` is not recreated.

`VAI-CONCUR-004` remains `NOT TESTED / DEFERRED` until two real graphical clients are available. It is not a blocker for this candidate because server-side concurrency semantics remain automated and the limitation is explicit.

Canonical operator procedure and evidence template:

```text
docs/livingworld/VALIDATION_0.2.0_CLEAN_WORLD_INSTALLED.md
```

## Runtime

- Minecraft 1.21.1
- Java 21
- Fabric Loader
- Fabric API for Minecraft 1.21.1
- Simple Voice Chat 2.6.20 or newer
- the same exact VillAIgence candidate JAR on server and graphical client

VillAIgence intentionally retains MCA's internal mod ID `mca`. Remove original MCA Reborn before installing VillAIgence; never install both simultaneously.

Server configuration remains `config/livingworld.json`. API credentials remain server-only. For the installed test, retain the known-good Chat provider/model configuration unless the provider itself is the subject of the test.

## Rollback

If any installed acceptance step fails:

1. stop the server;
2. preserve `latest.log`, crash reports if any, candidate SHA-256 and `<world>/livingworld/` evidence;
3. do not merge the release-request PR and do not publish the tag;
4. restore the offline test-world/server backup or return to the known-good `0.1.26+1.21.1` test setup;
5. fix the defect under a new development PR, then rerun the exact candidate boundary.
