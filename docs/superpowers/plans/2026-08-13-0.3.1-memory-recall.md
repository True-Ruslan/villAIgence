# 0.3.1 Memory Recall Correction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct the installed `0.3.0+1.21.1` multi-NPC recall regression without weakening NPC/player isolation or increasing bounded-memory limits, and correct the mis-specified voice-target acceptance contract.

**Architecture:** Keep Memory 2.0 server-owned and bounded. Current-message lexical relevance is applied only after owner/player eligibility filtering and early enough to keep an older relevant event from being discarded by the 32-candidate cap; the final context remains capped at 6 events. Voice targeting remains explicit RMB interaction-based targeting; proximity alone never selects or changes the active NPC.

**Tech Stack:** Java 21, JUnit 5, Fabric 1.21.1, existing Memory 2.0 persistence/retrieval APIs, GitHub Actions.

## Global Constraints

- Base exactly on released `0.3.0+1.21.1` commit `d42141511c0c61f10256fd06576f977f2a784d1c`.
- Preserve `CANDIDATE_LIMIT = 32` and `MAX_RESULTS = 6`; do not solve recall by widening windows.
- Filter by NPC owner and current-player eligibility before query relevance is considered.
- Do not expose another NPC's or another player's private dialogue through query matching.
- Current query is retrieval guidance only; it is not authority and must not mutate persistence.
- Do not add vector/semantic-search infrastructure or other `0.4` scope.
- Voice target contract is `RMB NPC -> active target`; proximity alone is N/A/unsupported by design.
- `VAI-M2-INST-005` remains `NOT TESTED / AUTOMATED EVIDENCE ONLY` and `VAI-CONCUR-004` remains `NOT TESTED / DEFERRED`.
- Runtime changes follow strict RED -> GREEN TDD.
