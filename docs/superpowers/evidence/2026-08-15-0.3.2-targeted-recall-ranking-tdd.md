## Investigation

`0.3.1` added a query-relevant candidate lane before the existing final Memory 2.0 rank-to-6 step. Exact NPC/player eligibility was already enforced before bounded candidate allocation.

The remaining ranking path still treated participant matching as a positive relevance dimension for every eligible dialogue. With a useful current query:

```text
old targeted dialogue with one lexical overlap
  participant relevance = 100
  lexical relevance     = 50
  combined relevance    = 75
  old recency           = 0

fresh unrelated eligible dialogue
  participant relevance = 100
  lexical relevance     = 0
  combined relevance    = 50
  fresh recency         ≈ high
```

Because relevance contributes 40% and recency 20% to the final score, sufficiently fresh unrelated dialogue could still outrank an older one-token lexical match. Candidate selection therefore succeeded while final rank-to-6 could still starve the target.

The existing PR #165 regression used a source fixture with at least two useful lexical overlaps (`личный` + `маркер`), which produces the maximum lexical score and did not exercise this weaker-match ranking boundary.

Important evidence limit: the exact archived raw text of Muammer's original marker event was not available to this development session. The new regression therefore proves an uncovered deterministic ranking defect mechanism consistent with the installed failure; it does not claim forensic proof that the real archived source had exactly one overlapping token.
